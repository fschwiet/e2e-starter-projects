# Android Starter Pack Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a minimal, well-configured Android "Hello, World!" starter pack with Jetpack Compose, a full verification pipeline (lint, ktlint, detekt, unit + instrumented tests), and chained precommit tasks.

**Architecture:** Single-module Android app using Kotlin DSL Gradle build, version catalog (`libs.versions.toml`), Compose-only UI in a `ComponentActivity`. All tool versions centralized; chained `precommit` / `precommitConnected` tasks wire `check` → `connectedAndroidTest` → `ktlintFormat` with `mustRunAfter` ordering.

**Tech Stack:**
- Kotlin 2.0.21, Android Gradle Plugin 8.7.3, Gradle 8.10.2
- Jetpack Compose (BOM 2024.12.01) with Compose Compiler Gradle plugin
- ktlint-gradle 12.1.2, detekt 1.23.7
- JDK 17, compileSdk/targetSdk 35, minSdk 24
- AndroidX Test (`androidx.test.ext:junit`, `androidx.compose.ui:ui-test-junit4`, `androidx.compose.ui:ui-test-manifest`)

**Placeholder convention:** All application-identity strings use `new-application-name` (folder) and `com.example.newapplicationname` (package). Forkers do a project-wide find-and-replace.

**Bootstrap prerequisite:** The engineer needs a system `gradle` (any 8.x) installed once to generate the wrapper via `gradle wrapper --gradle-version 8.10.2`. After that, only the wrapper is used. If `gradle` isn't on PATH, install via SDKMAN (`sdk install gradle 8.10.2`), Homebrew (`brew install gradle`), or download from gradle.org. JDK 17 must be the active JDK (`java -version` should show 17).

- [ ] **Step 1: Write the E2E test**

import androidx.compose.ui.test.junit4.createAndroidComposeRule
import androidx.compose.ui.test.onNodeWithText
import androidx.test.ext.junit.runners.AndroidJUnit4
import org.junit.Rule
import org.junit.Test

        composeTestRule.onNodeWithText(expected).assertIsDisplayed()
    }
}

## Task 7: Verification pipeline — detekt, ktlint, chained precommit tasks

**Files:**
- Modify: `app/build.gradle.kts` (append precommit task definitions)

The plugins (`ktlint`, `detekt`) are already applied from Task 3 — they contribute their respective tasks to `check` automatically. This task adds the chained `precommit` and `precommitConnected` tasks that bundle everything and apply formatting last.

- [ ] **Step 1: Verify individual verification tasks exist and run**

Run each in sequence:

```
./gradlew :app:ktlintCheck
./gradlew :app:detekt
./gradlew :app:lint
./gradlew :app:test
```

Expected: all BUILD SUCCESSFUL. `ktlintCheck` may flag style issues in `MainActivity.kt` or test files — if so, run `./gradlew :app:ktlintFormat` and re-run `ktlintCheck`, then re-stage any changes.

If `detekt` reports issues, review them. With the default ruleset they should be minimal on this codebase; if any fire, fix the code (don't suppress).

- [ ] **Step 2: Add `precommit` and `precommitConnected` tasks**

Append to the bottom of `app/build.gradle.kts`:

```kotlin
tasks.register("precommit") {
    group = "verification"
    description = "Run all checks then apply ktlint formatting."
    dependsOn("check", "ktlintFormat")
}

tasks.named("ktlintFormat") {
    mustRunAfter("check", "connectedAndroidTest")
}

tasks.register("precommitConnected") {
    group = "verification"
    description = "Run all checks, e2e tests, then apply ktlint formatting."
    dependsOn("check", "connectedAndroidTest", "ktlintFormat")
}
```

The `mustRunAfter` ordering ensures `ktlintFormat` (which mutates source files) runs only after the read-only verification tasks have completed. `precommit` does not depend on `connectedAndroidTest` but the `mustRunAfter` is harmless when that task isn't in the graph.

- [ ] **Step 3: Run `precommit` end-to-end**

Run: `./gradlew :app:precommit`
Expected: BUILD SUCCESSFUL. The output lists `ktlintCheck`, `detekt`, `lint`, `test`, then `ktlintFormat` as having run. No source file modifications (because ktlint already had clean source from Step 1).

If `ktlintCheck` fails, the build halts before `ktlintFormat` runs — that's correct behavior since `dependsOn("check", "ktlintFormat")` makes `check` a prerequisite of the lifecycle, and check failures stop the build.

- [ ] **Step 4: Run `precommitConnected` (requires connected device)**

Skip if no device is connected.

Run: `./gradlew :app:precommitConnected`
Expected: BUILD SUCCESSFUL. Same as `precommit` plus `connectedDebugAndroidTest` in the middle.

```bash

## Verification Pipeline

Individual commands:

```bash
./gradlew detekt                # static analysis
./gradlew lint                  # Android lint
./gradlew test                  # unit tests
./gradlew connectedAndroidTest  # e2e tests (requires connected device/emulator)
./gradlew ktlintCheck           # check formatting
./gradlew ktlintFormat          # apply formatting
```

Chained:

```bash
./gradlew precommit             # all checks, then apply formatting
./gradlew precommitConnected    # all checks, e2e tests, then apply formatting
```

`precommit` / `precommitConnected` **mutate source files** because they run `ktlintFormat` at the end. For a read-only CI pipeline, use `./gradlew check` instead — it already includes `ktlintCheck`, `detekt`, `lint`, and `test`.
```
